# 朗读的「读文件通道」(2026-11-06)

以前：发发发出消息后，每 0.3 秒读一次 Claude 窗口的文字，回复要 **1 秒不再变化** 才开始念。实测从回复出现到开口要 4～5 秒，还偶尔会念到「添加回应 / 按 Tab 键」这类界面文字。

现在：多了一个文件 `claude_reply.txt`。只要有人（Claude、脚本、hook）把回复写进去，发发 0.15 秒内就能发现，**不用等窗口稳定，直接念**。

- 只念你发出消息后 3 分钟内的文件更新（`reply_file_max_age_s`）
- 同一条回复：文件先到就念文件，窗口那边不再念；窗口先念了，文件就不重复念
- 文件没更新（比如对方没写），还是用读窗口兜底，和以前一样
- 文件第一行可以是 `# 时间` 这样的标记，会被跳过

## 谁来写这个文件

| 你在跟谁聊 | 怎么写 |
|---|---|
| Claude 项目聊天（现在用的） | Claude 每次回复前用工具把纯文本写进 `claude_reply.txt` |
| 本机 Claude Code（命令行） | 用 `claude_code_stop_hook.py` 做 Stop hook，配置写在这个文件开头的注释里 |
| 其他脚本 | `python write_reply.py "要念的文字"` |

## 另一个改动：Smart Turn 概率偏低时

Smart Turn 对中文常给很低的「说完了」概率（0.01～0.16），以前完整的一句话也要等满 3 秒才发。
现在概率低时会先转成文字看一眼：句末没有「然后 / 因为 / 逗号 / 省略号」这类没说完的迹象，就**只再等 1 秒**（`turn_text_ok_extra_ms`），这 1 秒里没再开口就发；开口了就接着听。

改之前的版本备份在 `main.py.before-replyfile.bak`。
