# voice-trigger · 语音唤醒自动发消息（最小版）

说一句「**fafa，帮我查一下明天的天气**」，工具会把「帮我查一下明天的天气」粘贴到你固定好的聊天输入框里并回车。

- 麦克风一直在听，用 VAD（默认 Silero，见文末）把声音切成一句一句
- 每句用本地 faster-whisper 转文字（不联网、**不存录音**，音频只在内存里）
- 只有句子里有唤醒词才会动作，其他话都忽略
- 只说「fafa」停一下也行：6 秒内说的下一句就当指令
- 不会马上发：说完后等 2 秒，确认你没再说话才发送；这 2 秒里你接着说的话会合并进同一条，并重新计时
- **附带复制的内容**：说「fafa」之前先复制一段文字（Ctrl+C），它会一起发出去，格式是「指令 + 空一行 + 【附带的复制内容】+ 你复制的文字」。只附带上次发送之后**新复制**的内容，而且**复制的时间要在你开口说这句话之前 10 秒以内**（说话过程中输入法写进剪贴板的文字不算，不会附带）。超过 10 秒就认为跟这次对话无关，不附带，日志里会写「超过 10 秒，认为无关」；超过 4000 字会截断。**复制的是图片也会发**：先粘贴指令文字，再粘贴图片，等 1.5 秒让图片加载出来，再回车（聊天框要支持 Ctrl+V 粘贴图片，网页版聊天一般都支持）；但如果发送目标是终端（Windows Terminal / cmd / PowerShell 等贴不了图），就不贴图，改成把剪贴板里的图片地址文字（浏览器复制图片时带的 URL）作为【图片地址】附上；没有地址文字（比如 Win+Shift+S 截图）就自动存到项目下的 screenshot_cache 目录，把文件路径作为【图片地址】附上，保存失败才跳过
- 发送完会把鼠标移回原来的位置（剪贴板也会还原）；但键盘焦点会留在聊天窗口，在别的窗口打字要先点回去

## 1. 安装（只做一次）

在 `Documents\GitHub\voice-trigger` 里打开 PowerShell：

```
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

需要 Python 3.9 以上。第一次运行会自动下载 Whisper 模型（small 约 500MB），之后就不用了。

## 2. 标记发送目标（只做一次，换了窗口就重做）

所有话、选中的文字、剪贴板的图片都发到这一个对话窗口，不再识别微信/Word/听写窗口。

1. 先点一下要发送到的那个对话框（Claude / 豆包 / 微信…都行）
2. 运行：

```
python main.py --mark-target
```

3. 3 秒内点回那个对话框，程序会记下它的程序名、标题和窗口句柄

窗口重开 / 句柄变了也能按「程序名 + 标题」重新找到；找不到会提示重新标记。

如果 Windows 不让这个窗口切到前台，再标定一个兜底点击点（只做一次，窗口挪了就重做）：

```
python main.py --calibrate
```

5 秒内把鼠标移到它的输入框上。只有激活失败时才会用这个点。

面板：「设置」页「发送目标」→「标记对话窗口」，同样 5 秒内点一下目标窗口；「标定点击点」是同一个兜底。

## 3. 先试听（不会真的发送）

```
python main.py --dry-run
```

说几句话，看窗口里 `[听到]` 打印出来的文字。重点看你说「fafa」时它写成了什么。

## 4. 正式用

```
python main.py
```

`Ctrl+C` 退出。紧急情况把鼠标甩到屏幕**左上角**，pyautogui 会立刻停下。

也可以双击 `run.bat` 启动。

## 控制面板（推荐）

双击 **`gui.bat`** 打开「发发 · 语音唤醒」窗口，常用操作都在里面：

- **运行状态**：绿色「● 运行中」/ 红色「○ 已停止」，一个按钮切换启动和停止，另有「重启」
- **开机自动启动**：勾上就是开机自启，取消勾选就是关掉
- **设置**：唤醒词、麦克风、说完等几秒再发、要不要自动回车、附带复制内容和时间窗口、贴图等待时间、抗背景音乐强度、识别模型、发送目标（标记对话窗口 / 标定点击点）。改完点「保存」，如果正在运行会自动重启让设置生效
- **最近识别记录**：显示日志最后 40 行，每 1.5 秒刷新

面板只负责管理后台的那个进程，关掉面板不影响后台继续听。想放到桌面：右键 `gui.bat` →「发送到」→「桌面快捷方式」。

下面这些 .bat 文件和面板做的是同样的事，面板打不开的时候可以用。

## 开机自动启动

先确认用 `python main.py` 前台跑起来没问题，再设置开机自启。

| 想做什么 | 双击这个文件 |
|---|---|
| 设置开机自启 | `autostart_on.bat` |
| 取消开机自启 | `autostart_off.bat` |
| 现在就在后台启动（不用重启） | `start_hidden.bat` |
| 临时停掉（比如开会、不想被听） | `stop.bat` |

- 原理：在 Windows「启动」文件夹（`Win+R` 输入 `shell:startup` 能打开）里放一个快捷方式 `voice-trigger.lnk`，登录后用 `pythonw` 在后台运行，**没有窗口**。手动删掉这个快捷方式也等于取消自启
- 开机后要等十几秒到半分钟（加载 Whisper 模型），之后才开始听
- 后台运行时的输出都写在 `voice-trigger.log` 里，不灵了就打开这个文件看，或者把最后几十行发给我
- 不会同时跑两个：后台已经在运行时，再双击 `run.bat`，它会提示「已经有一个在运行」然后退出。想看前台窗口调试，先双击 `stop.bat`
- 也可以在任务管理器里找 `pythonw.exe` 结束它

## 5. 唤醒词识别不准怎么调

Whisper 不认识「fafa」这个词，可能写成「发发」「花花」「法法」「Fafa」「發發」等。

1. 用 `--dry-run` 跑，对着麦克风说 5～10 次「fafa」
2. 看 `[听到]` 后面它实际写的是什么
3. 打开 `config.json`，把这些写法加进 `wake_words`，例如：

```json
"wake_words": ["fafa", "fa fa", "发发", "發發"],
```

注意：
- 大小写、空格、标点不影响匹配（`Fa, fa` 也算 `fafa`）
- **不要加太常见的词**（比如「哈哈」「花花」），否则聊天时会误触发。默认只留了 4 个最像的写法
- 实在不稳，可以把 `model_size` 从 `small` 改成 `medium`（更准，但更慢、模型约 1.5GB）

## config.json 里其他可调的

| 字段 | 默认 | 说明 |
|---|---|---|
| `mic_device` | `null` | 用哪个麦克风。`python main.py --list-mics` 看编号，填数字 |
| `silence_end_ms` | `800` | 停顿多久算一句话说完。总被切断就调大到 1200 |
| `vad_aggressiveness` | `3` | 0～3，越大越严格 |
| `wait_command_s` | `6` | 只说唤醒词后，等指令的秒数 |
| `send_delay_s` | `2` | 说完后等几秒再发送（期间再说话会合并、重新计时）。旧的 config.json 里没有这一项也没关系，默认就是 2；想改就手动加一行 |
| `min_speech_ms` | `500` | 一句话里人声至少要这么长才去识别 |
| `min_continuous_ms` | `240` | 至少要有一段这么长的**连续**人声。敲键盘是一下一下很短的"咔"，靠这条过滤 |
| `no_speech_prob_max` / `avg_logprob_min` | `0.5` / `-1.0` | Whisper 自己觉得"不像人声 / 没把握"的片段直接丢掉，窗口里会打印 `[丢弃, 不像人声]` |
| `min_command_chars` | `2` | 指令少于 2 个字不发 |
| `dedup_s` | `10` | 10 秒内同一句话不重复发 |
| `energy_ratio` | `2.5` | 声音要比背景（音乐、风扇）大这么多倍才算人声。放歌还误触发就调到 3～4；你说话没反应就调到 2 |
| `min_rms` | `300` | 最小音量，太小声的一律不算 |
| `attach_clipboard` | `true` | 要不要附带复制的内容，`false` 就关掉 |
| `attach_only_new` | `true` | 只附带上次发送后新复制的；改成 `false` 就每次都附带剪贴板里的文字 |
| `attach_max_chars` | `4000` | 附带内容的最大字数，超出会截断 |
| `attach_window_s` | `10` | 复制后多少秒内开口说话才附带。经常来不及就调到 20 |
| `alt_hold_no_autosend` | `true` | 按住 Alt 说话时不自动发送（用输入法听写、自己编辑）；说「发发」的指令不受影响 |
| `image_wait_s` | `1.5` | 粘贴图片后等几秒再回车。图片还没上传完就被发出去的话，调大到 3 |
| `press_enter` | `true` | 粘贴后要不要自动回车 |
| `model_size` | `small` | `base` 更快 / `medium` 更准 |

## 防误触发（敲键盘、放音乐）

工具做了这几层过滤：

1. **只听麦克风**：启动时会打印「使用麦克风: xxx」。如果选到的是「立体声混音 / Stereo Mix」（这个录的是电脑自己放的声音），会直接提示并退出。`python main.py --list-mics` 能列出所有设备，内录设备会标「不要选」
2. **音量门限**：工具会慢慢学会背景有多吵（放歌大约 3～15 秒后学会），只有明显比背景更大声的人声才会触发。所以刚开始放歌那几秒可能会识别到一句歌词，之后就不会了
3. **键盘声过滤**：要有一段连续的人声才识别，短促的敲击声会被丢掉
4. **Whisper 置信度过滤**：模型没把握的结果直接丢掉
5. **只说唤醒词不发送**：只有「fafa + 指令」或 6 秒内的下一句才会发；指令少于 2 个字不发；10 秒内重复的不发

最有效的办法还是**戴耳机听歌**，或者让麦克风离嘴近、离音箱远。耳机的声音进不了麦克风，就完全不会误触发。

还会误触发的话，先用 `python main.py --dry-run` 跑一会儿，把窗口里 `[听到]` 的内容发给我，我帮你调参数。

## 常见问题

- **更新后报错 `No module named PIL` 或 `win32clipboard`**：重新运行一次 `pip install -r requirements.txt`（新加了 pillow 和 pywin32，用来读写剪贴板里的图片）。
- **图片没贴上 / 只发了文字**：先手动试一下，在聊天框里按 Ctrl+V 能不能粘贴图片。不能的话就是聊天框本身不支持粘贴图片。

- **`pip install` 报错 webrtcvad**：确认装的是 `webrtcvad-wheels`（已写在 requirements.txt），它自带 Windows 版本，不用编译。
- **粘贴到了别的地方**：发送目标变了，重新 `--mark-target`；窗口界面挪了导致兜底点击点不准，再 `--calibrate`。
- **一句话被拆成两句**：调大 `silence_end_ms`。
- **识别出繁体字**：一般不影响，唤醒词别名里已经放了「發發」。

## Silero VAD + 两种触发方式（2026-11-06 新增）

### 断句换成了 Silero VAD

以前用 webrtcvad 判断"是不是在说话"，现在默认用 **Silero VAD**（和 vad-lab 里学的是同一个神经网络模型），对键盘声、风扇声更不容易误判。

- 不用另外装东西：直接用 faster-whisper 自带的 `silero_vad_v6.onnx` 模型，用 onnxruntime 跑，每 32ms 一帧
- 流程：麦克风 → 音量门限（抗背景音乐，保留）→ Silero 给每帧打人声概率 → 状态机切成一句一句（连续 3 帧有声才算开口，安静 0.8 秒算说完，太短的丢掉）→ Whisper 转文字 → 找「发发」
- 日志里启动时会写 `VAD: Silero (神经网络)`；如果 Silero 加载失败会自动退回 `VAD: webrtc`
- 想换回原来的：`config.json` 里 `"vad_engine": "webrtc"`，或者在面板「断句 VAD」里选 webrtc

### 触发方式（config.json 的 `trigger_mode`，面板里也能选）

| 值 | 怎么说 | 例子 |
|---|---|---|
| `prefix` | 先说发发，再说指令（原来的方式） | 「发发，帮我查天气」 |
| `suffix` | 先说话，最后说发发 → 前面攒的话一起发 | 「今晚吃什么好……帮我查天气……发发」 |
| `both`（现在的设置） | 两种都行：发发在句首且后面有话 = prefix；发发前面有话或已经攒了话 = suffix | 上面两种都可以 |

suffix 的规则：
- 每句话识别出来先放在**内存**里（不存文件），日志里显示 `[缓冲] 已攒 N 句`
- 说「发发」时，把攒的话加上「发发」前面那半句，用逗号连成一条，等 2 秒发送（剪贴板附带、去重照旧）；发完清空
- 只攒最近 **60 秒**（`buffer_max_s`）；两句之间停顿超过 **8 秒**（`buffer_gap_s`）就清空重来，日志写「停顿超过 8 秒，清空」
- 结束词用「发发」不用单字「发」：「发」太常见（发现、发烧、发消息），会一直误触发

取舍：
- 好处：说话更自然，想好了再说，最后一个「发发」确认
- 风险：跟别人聊天时随口说了「发发」，前面 60 秒内的闲聊也会被发出去。60 秒 / 8 秒两个保护就是为了减少这种情况；经常误发就把 `buffer_gap_s` 调小（比如 4），或者改回 `prefix`
- `both` 模式下，如果已经攒了话，单独说一句「发发」会把攒的话发出去，而不是"等下一句当指令"

## NVIDIA 显卡加速（2026-11-06 新增）

- 双击 **`gpu_setup.bat`**：① 用 `nvidia-smi` 检查有没有 N 卡和驱动 ② 往 .venv 里装 `nvidia-cublas-cu12` 和 `nvidia-cudnn-cu12==9.*`（约 1GB）③ `main.py --gpu-check` 试一下，成功会自动把 config.json 的 `device` 改成 `auto` ④ `main.py --bench` 测 small / medium 在 CPU 和显卡上转同一段 15 秒录音各要几秒
- `device`: `cpu` / `cuda` / `auto`（有能用的 N 卡就用，加载或试转失败自动退回 CPU，日志里写 `Whisper: 显卡加速 (GPU)` 或 `Whisper: CPU`）
- 显卡精度 `gpu_compute_type` 默认 `float16`，老显卡报错可以改成 `int8_float16`
- Silero VAD 一直在 CPU 上跑（一帧不到 1 毫秒，不需要显卡）
- 改完要重启：`stop.bat` → `start_hidden.bat`

## 自动发送模式（2026-11-06 新增，不用说发发）

- 打开后：每说完一句话，停顿 **0.5 秒**（`auto_silence_ms`）就自动把这句转成文字发出去，不用说「发发」。句子里如果有「发发」会被去掉
- **注意：打开期间你说的所有话都会被发出去**（少于 2 个字的不发，`auto_min_chars`），跟人聊天、打电话前记得关掉
- **按住 Alt 说话 = 只听不发**：用微信输入法等语音听写、想自己编辑这段话时，按住 Alt（左/右都行）说；这句话不会自动发出去，日志写「[模式] 按住 Alt 说话 (自己编辑), 不自动发送」，也不会问 DeepSeek。明确说「发发 ...」的指令不受影响。开关：config.json 的 `alt_hold_no_autosend`（默认 `true`）
- 开/关的方法（都是马上生效，不用重启）：
  - 全局热键 **Ctrl+Alt+F**（`auto_hotkey`，在任何窗口都能按）：打开时「嘀」一声高音，关闭时一声低音
  - 控制面板里的「开/关自动发送」按钮，面板上会显示 `⚡ 自动发送: 开` 或 `自动发送: 关`
- 开关状态保存在文件夹里的 `AUTO_SEND_ON` 文件里：有这个文件 = 开，重启后也保持
- 关掉后回到 `trigger_mode` 设置的方式（比如 suffix / both）
- 延迟：停顿 0.5 秒 + 显卡上 medium 转写约 0.3~0.5 秒 + 点击粘贴回车约 0.5 秒，说完到发出去**大约 1.3~1.5 秒**。不可能做到 0.5 秒内，因为程序要先等你停 0.5 秒才能确定你说完了；嫌句子被切断就把 `auto_silence_ms` 调大（比如 800）

## Smart Turn：判断"说完没"（实验，2026-11-06）

- 是什么：pipecat-ai 开源的 **Smart Turn v3.2**（BSD-2 许可，可以随便用），8MB 的小模型（Whisper-tiny 编码器 + 分类头），**听语气和语调**（不看文字）判断你这句话说完了没有。模型文件放在 `models\smart-turn-v3.2-cpu.onnx`，不用另外装库
- 只在**自动发送开着**时起作用（Ctrl+Alt+F 打开）。`suffix / both` 模式下不管它
- 流程：VAD 发现你停了 **0.3 秒** → Smart Turn 判断一次：
  - 说完了（概率 ≥ 0.5）→ 马上转文字发送，比原来固定等 0.5 秒还快一点
  - 没说完 → 继续等；你接着说就接到同一句里；**最多等 3 秒**也会发
- 日志里会写：`[Smart Turn] 停顿 0.3s, 说完的概率 0.68 -> 说完了`，可以看它判断得准不准
- 开关：config.json 的 `smart_turn`，或面板里「自动发送用 Smart Turn」勾选框
- 参数：`smart_turn_check_ms` 300（停多久判断）、`smart_turn_threshold` 0.5（调低 = 更容易判断"说完了"，发得更快）、`smart_turn_max_wait_ms` 3000（最多等多久）
- 限制（如实说）：
  - 官方测试里**中文准确率约 86%**（英语等更高），每 7 句大约有 1 句会判断错；判断错成"没说完"时就要多等到 3 秒
  - 它只听声音，不懂意思；中文说话语调平的时候容易判断成"没说完"
  - 速度：CPU 上一次 30~90 毫秒，不需要显卡
  - 我在云端用合成语音测过：两句中间停 0.8 秒，它判断"没说完"，把两句接成了一条（这是想要的效果）；但合成语音的结尾它也常判断成"没说完"，要等满 3 秒。真人说话效果要你自己试

## 只发对 AI 说的话 + 通话时暂停（2026-11-06，默认关）

### 只发对 AI 说的话（DeepSeek 判断）
- 只在**自动发送开着**时起作用。每句话转成文字后（少于 2 个字的不问），把这句和前面 3 句一起发给 DeepSeek（`deepseek-flash`，已关闭思考模式 `"thinking": {"type": "disabled"}`，模型名在 config 的 `ai_filter_model` 里可改），问"最后一句是不是对 AI 说的"，它只回答「是」或「否」；「是」才发送
- 日志里会写判断结果，方便你调：
  - `[AI 判断] 是对 AI 说的: 是 (0.6s, 今天第 12 次) -> 发送`
  - `[AI 判断] 不是对 AI 说的: 否 (...) -> 不发`
  - `[AI 判断] 没判断成: 超时 -> 不发`
- 开启方法：打开面板 → 勾「自动发送只发对 AI 说的话」→ 在「DeepSeek key」里填你的 key（显示成圆点，只存在本机 config.json，日志里不会出现）→ 保存
- 参数：`ai_filter_timeout_s` 3 秒超时；`ai_filter_on_error` 超时/出错时 `drop` 不发（默认）或 `send` 照样发；`ai_filter_daily_limit` 每天最多问 500 次（次数记在 `ai_filter_usage.json`）；`ai_filter_context` 带前面几句
- 代价：每句话多等 0.5~1 秒（网络），每句都会发给 DeepSeek（这句话的文字会离开你的电脑）；费用很低，一句话大约几十个 token
- **key 不要贴到聊天里**，自己填在面板里

### 通话软件用麦克风时自动暂停
- 勾面板里的「通话软件用麦克风时暂停」（config `pause_on_call`）
- 每 2 秒看一次 Windows 隐私设置里"正在使用麦克风的程序"，如果是 Teams / Zoom / 微信 / Discord / 飞书 / 钉钉 / QQ 等（`call_apps` 列表，可以自己加），自动发送就暂停，日志写 `[通话] xxx 正在用麦克风, 自动发送暂停`；通话结束自动恢复
- 只是看程序有没有在**用麦克风**，微信开着但没在通话不会暂停

## DeepSeek 辅助判断说完没（2026-11-06，默认关）

- 要先勾「自动发送用 Smart Turn」，再勾「用 DeepSeek 辅助判断说完没有」，并且填了 DeepSeek key
- 停顿 0.3 秒时 Smart Turn 先给一个"说完的概率"：
  - ≥ 0.8（`ai_turn_high`）→ 直接发
  - < 0.3（`ai_turn_low`）→ 没说完，继续等（最多 3 秒）
  - 0.3~0.8 拿不准 → 先把已经说的话转成文字，再问 DeepSeek（`deepseek-flash`，关闭思考）「这句话说完整了吗」，回答「是」就发，「否」就继续等
  - DeepSeek 超时（3 秒）/出错 → 按 Smart Turn 原来的结果（≥ 0.5 算说完）
- 日志：`[AI 说完判断] 「今天晚上吃什么好呢」 -> 没说完, 继续等  (否 (0.5s ...), 转文字+判断共 0.9s)`
- 延迟：拿不准的那一句会多花 转文字（显卡约 0.3 秒）+ DeepSeek（约 0.5~1 秒）；判断"说完了"时文字直接拿来发，不会再转一次

## 发送目标窗口 + 带上选中文字（2026-11-08 简化）

### 发送目标窗口（`target_window`）
所有内容都发到标记的那一个对话框，不再看前台窗口做什么。发送时按 **exe + 标题子串**重新枚举顶层窗口找到它（窗口重开、句柄变了也能找到），然后 `ShowWindow(SW_RESTORE)` + `SetForegroundWindow`，再用 10 次 × 100ms 轮询确认前台真的是它（或它的子窗口）。

- 激活成功：剪贴板设文字 → `Ctrl+V` → 等 300ms → 回车（**完全不点鼠标**）
- 激活失败：用 `--calibrate` 存下的「相对客户区坐标」点一下输入框，再粘贴 + 回车；没有标定数据就报错，不会乱点
- 剪贴板里有图片：文字发完后再单独粘贴图片 + 回车，图片是第二条消息
- 日志只会写「已粘贴文字并回车 (未校验输入框内容)」「已粘贴图片并回车 (未校验)」，**不会无条件说「已发送」**
- 窗口找不到会明确打印「标记的窗口不见了, 请重新运行: python main.py --mark-target」
- 不需要 uiautomation，也没有窗口路由 / 听写分支

### 说话时带上选中文字（`attach_selection`）
- 在代码或文章里**框选一段**，然后说「帮我解释一下这段代码」，发给 AI 的消息会变成：你说的话 + 【选中的内容】+ 框选的那段，不用自己复制
- 原理：只在发送那一刻，在前台窗口按一下 Ctrl+C 读选中内容，读完把原来的剪贴板放回去；不会在后台一直读
- 超过 6000 字会截断（`selection_max_chars`），日志写 `[选中文字] 从 xxx 读到 N 字`
- 终端（cmd / PowerShell / Windows Terminal）里不读，因为 Ctrl+C 会中断程序（`selection_skip_apps`）
- 限制：VS Code 里**没选中任何东西**时按 Ctrl+C 会复制整行，所以那一行会被带上
- VS Code（`selection_line_copy_apps`）没选中时 Ctrl+C 会复制整行：复制到的刚好是带换行的一整行就当作没选中

## 判断时带上对话上下文（2026-11-07，默认开）

- 用在「只发对 AI 说的话」的判断里
- 第 1 步（一定有）：如果你 **120 秒内**刚发过话给 AI，会把「你 N 秒前对 AI 说了：……」一起给 DeepSeek，并告诉它紧跟着的追问（「那…呢」「为什么」「再详细点」）要判为对 AI 说的
- 第 2 步（要装东西）：试着用 Windows UI Automation 读 **标记对话窗口里最后约 800 字**，大致就是 AI 最近的回复，一起给 DeepSeek 参考。只在判断时读一次，不会一直监听；回复内容只发给 DeepSeek，**不写进日志**，日志只写 `[上下文] ... AI 回复: 读到 N 字` 或读不到的原因
- 第 2 步：在面板里点 **「安装并测试读取 AI 回复」** 按钮：没装库会在后台自动装（进度显示在按钮旁边，不会弹黑窗口），然后倒数 3 秒，试读一次聊天框所在窗口，结果（读到多少字 / 读不到的原因）直接显示在面板上。先让 AI 聊天窗口露出来。读不到也没关系，只用第 1 步。（`ui_setup.bat` 做的是同样的事，现在不用了）
- 面板：「判断时带上对话上下文」勾选框；config：`ai_context`、`ai_context_max_s`、`ai_context_read_reply`、`ai_context_reply_chars`
- 限制：读到的是窗口末尾的文字，可能混着你自己发的那句；浏览器/Electron 应用要开启无障碍接口才读得到，能不能读到要实测

## 念出 AI 回复（TTS，2026-11-07，默认关，练听力用）

- 用的是 **edge-tts**（免费，用微软在线的声音，要联网）。在面板点 **「安装并试听」**：没装会自动装（进度显示在按钮旁，不弹黑窗口），然后用你选的声音念一句英文
- 打开：面板勾「念出 AI 回复 → 开」，点保存。可选「只念英文」、语速（-30% ~ +40%）、英文声音（美/英/澳）；中文回复用 `zh-CN-XiaoxiaoNeural`
- 原理：你发出一条话后，后台每秒读一次聊天窗口的全部文字，找到你发的那句，**它后面新出现的文字**就是回复（会去掉窗口底部固定不变的按钮/提示文字）；回复 **2 秒不再变化**就念。去掉代码块、像代码的行、链接、markdown 符号和末尾的 Copy/Retry。最多等 3 分钟；你又发了新消息就不等旧的
- 控制：面板「再念一遍」「停止念」；全局热键 **Ctrl+Alt+R** 再念一遍、**Ctrl+Alt+S** 停止
- **防回声**：你一开口就自动停止朗读（`tts_barge_in`）。**要戴耳机**：用音箱外放时，麦克风听到朗读的声音也会"打断"它自己；外放的话把 config 里 `tts_barge_in` 改成 false，这样朗读期间听到的话都当作回声不发，用 Ctrl+Alt+S 手动停
- 日志：`[朗读] 356 字, 英文`、`[朗读] 停止`、`[朗读] 在聊天窗口里没找到你刚发的那句, 不念`
- 限制：靠"在窗口文字里找到你发的那句"来定位回复。如果 Claude 把你的消息显示得不一样（比如很长被折叠、带附件），可能找不到，就不念；回复里的界面文字（按钮名）可能偶尔被念出来

## 识别语言：自动分中文 / 英文（2026-11-07）

- 面板「识别语言」下拉，config `language`：
  - `auto` 自动（现在的设置）：每句话先让 Whisper 听一下是中文还是英文，英文概率 ≥ 0.5 且比中文高就按英文写，否则按中文（简体提示词照旧）。日志写 `[语言] en (英文 0.97 / 中文 0.02)`
  - `zh` 只认中文（以前的设置：说英语会被写成中文音译）
  - `en` 只认英文（英语练习模式：提示词换成英文，说什么都按英文写）
- 中英混着说的一句话，会按占多数的那种语言写；短句（比如只说"OK"）可能判断不准

## 朗读过滤界面文字
